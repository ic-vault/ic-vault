# Security policy

## Reporting a vulnerability

Report it privately through GitHub: [open a private report](https://github.com/ic-vault/ic-vault/security/advisories/new). Only the maintainers can see it.

Do not open a public issue, pull request or discussion about a vulnerability.

A useful report says what the attacker holds, what they do, and what they get. A proof of concept helps, and so does the section of VAULT-PLAN.md or the file it concerns.

## What to expect

- The project has one maintainer and no budget. Replies are best effort.
- You hear whether the report is accepted and what will change.
- A fix is released before the report is published. You are credited, unless you ask not to be.

## Scope

Everything in this repository is in scope: the design documents, the canister, the web app, the scripts and the build.

The Internet Computer itself, Internet Identity, browsers and authenticators are out of scope. Report those to their own projects.

Section 15 of VAULT-PLAN.md lists the weaknesses the design already accepts. A report that one of them is worse than stated is in scope.

## Supported versions

There is no release yet. Once there is one, only the latest release is supported.

## Review status

The design has not been independently reviewed. See the README.
